This document provides an introduction to the Morph Particles system, a WebGL-based interactive particle animation framework that enables smooth morphing between 3D models through particle transformations. The system creates visually stunning effects where particles dynamically rearrange to form different shapes as users scroll through a webpage.

Purpose and Scope
Morph Particles is designed to:

Create high-performance particle-based transitions between 3D models
Utilize GPU-accelerated simulations via WebGL and Frame Buffer Objects (FBO)
Provide an interactive scrolling experience where visual elements morph in response to user input
Demonstrate advanced shader-based techniques for particle rendering and animation
For detailed information on the particle system implementation, see Particle System, and for the underlying FBO technology, see Frame Buffer Objects.

System Overview
Morph Particles is built on a modular architecture centered around the Experience class, which orchestrates various subsystems to create the interactive visual experience.

Model Processing and Texture Generation
The Page class processes 3D models and converts them into textures that can be used by the shader system:













The makeTexture method converts a THREE.js geometry into a data texture:

makeTexture(g) {
    let vertAmount = g.attributes.position.count;
    let texWidth = Math.ceil(Math.sqrt(vertAmount));
    let texHeight = Math.ceil(vertAmount / texWidth);
    let data = new Float32Array(texWidth * texHeight * 4);
    
    // Shuffle and copy position data
    shuffleArrayByThree(g.attributes.position.array);
    
    for(let i = 0; i < vertAmount; i++) {
        const x = g.attributes.position.array[i * 3 + 0];
        const y = g.attributes.position.array[i * 3 + 1];
        const z = g.attributes.position.array[i * 3 + 2];
        const w = 0;
        
        data[i * 4 + 0] = x;
        data[i * 4 + 1] = y;
        data[i * 4 + 2] = z;
        data[i * 4 + 3] = w;
    }
    
    let dataTexture = new THREE.DataTexture(
        data, 
        texWidth, 
        texHeight, 
        THREE.RGBAFormat, 
        THREE.FloatType
    );
    dataTexture.needsUpdate = true;
    
    return dataTexture;
}

This document explains the Frame Buffer Object (FBO) implementation in the morph-particles system. The FBO class provides a GPU-accelerated method for efficiently simulating and rendering large numbers of particles, enabling smooth morphing animations between different 3D models represented as particle systems.

FBO Overview
Frame Buffer Objects are OpenGL objects that allow rendering to destinations other than the screen. In the morph-particles system, FBOs are used to perform particle position simulation on the GPU by rendering to a texture, which is then used to position particles in the scene.

The FBO class encapsulates this rendering-to-texture technique to enable efficient particle animations that would be prohibitively expensive if calculated on the CPU.

Morphing Logic
The core of the shader system is the model morphing logic that creates smooth transitions between different 3D models. This is primarily handled in the simulation fragment shader.



The key aspects of the morphing logic:

Range Calculation: Each model transition occurs within a specific scroll range:

float range = 1.0 / uTotalModels;
Staggered Transitions: Random offsets create natural-looking transitions:

float r = random(vUv) * 0.2;
float t = remap(clamp(uScroll - (r * 0.5), 0.0, range - r), 0.0, range - r, 0.0, 1.0);
Model Interpolation: Linear interpolation between model positions:

pos = mix(textureA, textureB, t);
Dynamic Rotation: Models are rotated based on time:

vec3 textureA = rotationMatrix3(vec3(1.0, 0.0, 0.0), sin(uTime) * 0.1) * texture2D(uTextureA, vUv).xyz;
